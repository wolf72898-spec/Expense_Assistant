## 初始诉求

## 在线需求分析
现有事实已能定位变更协同的核心瓶颈：版本与交底脱节、授权链不可追溯、三套计量口径并存且各岗完成时间未分记，导致12天确认周期与返工损失难以归因。管理层目标（12→6天、返工损失降30%）与试点验收（版本错误召回100%、签证依据完整率95%）已明确，但节点耗时、签证月度受理量、退回原因分布、事件台账均未采集，无法据此设定分母与基线。切入点建议按“不可逆风险优先”排序：先做版本核对与变更追踪的只读提示（不代签、不自动批准），再谈计量口径统一；争议处置路径与保留期限属制度层，须人工确认，不纳入首期自动范围。

### 3. 三套计量口径并存且各岗完成时间未分记，导致周期无法归因 [P1]

### 4. 图纸编码不统一与日期混用会污染自动推荐，需先建人工修复队列 [P1]

下一步验证：对试点分区资料做主编号、事件时间、版本字段三项校验，统计歧义记录比例；歧义样本全部转人工修复，修复后再进入回放验证。

### 5. 跨系统状态无统一视图，需明确快照时效与故障降级规则 [P1]

下一步验证：先做只读接口连通性测试，记录可获取字段与延迟；模拟一次中断，验证快照标注与去重补齐是否符合规则，人工确认降级期间业务不中断。

### 6. 交底不到位的历史事件与整改闭环无台账，无法纳入核验签字范围 [P2]
待确认负责人：傅景（质量安全负责人）确认归集责任人与闭环判定标准

质量安全负责人明确表示无可引用的事件台账或复盘记录，是否发生相关质量安全事件尚未核实；同时结构安全与设计变更须合格人员审核、本场景不做专业计算。在台账缺失前，交底环节不宜纳入自动核验签字范围。

下一步验证：先确认事件归集责任岗位与闭环判定标准，再决定是否将交底纳入试点核验；保留期限90天仅为试点暂定，须按组织规则另行确认。

## 需求如何归纳

先从已采集事实形成问题假设，再约定业务结果、范围、失败控制和验收。缺少的来源标记待补，不能把六人访谈完整率当作四来源收敛或需求确认。

### 业务流程拆解

要回答：问题发生在哪一步，为什么要这样划分智能体？

1. 先画人工现状泳道，写出触发、输入、8–15个处理步骤、交接和异常。
2. 区分判断点与执行点；按使用的数据、权限、模型能力与失败方式组合执行步骤。
3. 在不可逆动作前设置确定性校验；为低置信、缺资料、冲突和越权安排具名人工接收人。

交付链：现状流程 → 失败方式 → 智能体/工具边界 → 校验与人工升级路径

原文：frameworks/workflow-decomposition.md

### 业务结果与不可逆风险矩阵

要回答：多个需求中，先做哪个最小可验证方案？

1. 列出3–5个候选切入点，分别说明改善的业务结果、现状基线和投入。
2. 评估失败何时被谁看见、能否在损害前拦截、是否可以撤销；不要把模型置信度等同于业务风险。
3. 优先选择高价值、可拦截且可恢复的切入点；高风险需硬约束和责任人否决权，价值或风险未知先补证据。

交付链：候选方案 → 价值/风险比较 → 选择与暂缓理由 → 验收指标与停止条件

原文：frameworks/outcome-risk-matrix.md

### 四来源收敛

要回答：谁说要做，哪里真的坏了，范围允许什么，技术是否可行？

1. Buyer：核实业务目标、预算、优先级和决定权；Operator：用最近一单还原真实操作和失败位置。
2. Brief：核对书面目标、范围、时间和排除项；Industry：寻找可比技术实践，并核实本项目的数据与接口差异。
3. 检查四个视角是否指向同一瓶颈。分歧保留在问题清单：一线帮助定位故障，决策者确认价值，Brief约束范围，行业证据帮助判断可行性。

交付链：四视角陈述与来源 → 收敛/分歧 → 待核实问题 → 有边界的需求假设

原文：frameworks/4-source-convergence.md

### 从证据到候选需求

- REQ-1 版本与交底脱节是首要瓶颈，需先做只读版本比对提示
  依据：construction-change-f10、construction-change-f14、construction-change-f01、construction-change-f00
  推导：现场拿到旧图施工、新图已上传但无人交底，且关键说明留在个人便签或群内未随单据交接，说明版本状态与交底动作之间缺少强制衔接点。但各节点等待与处理时间未分别量出，无法证明版本环节就是12天中的最大占比，需先测时再定优先级。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：在一个施工分区回放历史变更，按节点记录等待与处理时长，统计版本错误发生笔数；以版本错误提示召回100%为验收线，人工逐笔复核提示是否漏报。
- REQ-2 授权链缺失导致签证被拒，需在提交前做授权与依据完整性校验
  依据：construction-change-f11、construction-change-f02、construction-change-f44、construction-change-f21
  推导：口头要求增加管线、事后签证被拒且无法确认授权链，属于不可逆的商务损失；同时签证依据完整率95%已被列为验收指标，说明依据缺失是已知问题。但签证月度受理量与退回原因分布未采集，无法量化该痛点的损失占比。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：抽取近三个月被拒签证样本，按“缺授权、缺版本依据、计量口径不符”分类计数；系统仅做提交前缺项提示，不生成结论，由造价工程师逐笔确认。
- REQ-3 三套计量口径并存且各岗完成时间未分记，导致周期无法归因
  依据：construction-change-f50、construction-change-f53、construction-change-f51、construction-change-f00
  推导：现场按施工完成计量、造价按签证有效计量、业主按审批版核价，三套口径并存；且明确要求分别记录各岗完成时间、固定分母与排除规则。没有分岗计时，12天目标无法拆解到责任环节，也无法对外解释核价差异。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：先由顾明岚定分母、排除规则与统计周期，秦芮出分岗计时字段清单；用一个月历史数据试算，检查同一业务是否被拆成多次成功。
- REQ-4 图纸编码不统一与日期混用会污染自动推荐，需先建人工修复队列
  依据：construction-change-f31、construction-change-f33、construction-change-f30
  推导：图纸编码不统一、签证发生日与确认日混用已被明确记录，且规定有歧义记录进入人工修复队列、不进入自动推荐样本。若跳过数据治理直接试点，版本比对结果不可信，召回100%无法达成。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：对试点分区资料做主编号、事件时间、版本字段三项校验，统计歧义记录比例；歧义样本全部转人工修复，修复后再进入回放验证。
- REQ-5 跨系统状态无统一视图，需明确快照时效与故障降级规则
  依据：construction-change-f30、construction-change-f34、construction-change-f35、construction-change-f32
  推导：BIM文档库、项目管理平台与造价软件权限独立、状态无统一视图；已规定每天两次更新、超周期标待刷新、接口中断用带时间戳只读快照。但现有系统实际接口能力与授权范围尚未核实，不能假定可实时同步。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：先做只读接口连通性测试，记录可获取字段与延迟；模拟一次中断，验证快照标注与去重补齐是否符合规则，人工确认降级期间业务不中断。
- REQ-6 交底不到位的历史事件与整改闭环无台账，无法纳入核验签字范围
  依据：construction-change-f40、construction-change-f42、construction-change-f45、construction-change-f43
  推导：质量安全负责人明确表示无可引用的事件台账或复盘记录，是否发生相关质量安全事件尚未核实；同时结构安全与设计变更须合格人员审核、本场景不做专业计算。在台账缺失前，交底环节不宜纳入自动核验签字范围。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：先确认事件归集责任岗位与闭环判定标准，再决定是否将交底纳入试点核验；保留期限90天仅为试点暂定，须按组织规则另行确认。
